Vector Graphics in Cinder

This document provides an overview of the vector graphics capabilities in Cinder's cinder::vg namespace. The API provides GPU-accelerated 2D rendering with analytical anti-aliasing, gradient fills, feathering (soft edges), and high-performance path rendering.

Introduction

The cinder::vg rendering engine is built on the GPU renderer from Rive, a real-time interactive design tool. However, this is not the Rive runtime for playing .riv animation files—it is the standalone rendering engine extracted and adapted for general-purpose 2D vector graphics.

Key features include:

  • Analytical anti-aliasing via Pixel Local Storage (PLS) or atomic operations
  • Feathering for soft, blurred edges on fills and strokes
  • Linear and radial gradients with configurable spread modes
  • High-performance path tessellation with optional caching
  • Instanced drawing for efficiently rendering many identical shapes
  • DisplayList recording for caching complex scenes
  • Multiple backends: OpenGL and Direct3D 12 (experimental)

The API follows familiar conventions from HTML5 Canvas and other 2D graphics libraries, making it approachable while offering significant performance advantages through GPU acceleration.

Design

The architecture centers on an abstract Canvas base class with platform-specific implementations:

  • CanvasGl – OpenGL backend (4.1+ macOS, 4.5+ Windows/Linux)
  • CanvasD3d12 – Direct3D 12 backend (Windows, experimental)

Supporting classes provide resource management and styling:

  • Paint – visual styling (colors, gradients, stroke properties)
  • CachedPath – GPU-cached path representation
  • FrozenPath – pre-tessellated path for maximum performance
  • Image – GPU texture wrapper for image drawing
  • DisplayList – recorded sequence of draw commands

All drawing commands are captured and batched before being sent to the GPU via Rive's RiveRenderer. This deferred rendering approach enables efficient state management and draw call batching.

Getting Started

Window Rendering (OpenGL)

The simplest way to use cinder::vg is to create a canvas and draw directly to the window:


#include "cinder/vg/CanvasGl.h"

class MyApp : public App {
    vg::CanvasGlRef mCanvas;

    void setup() override {
        mCanvas = vg::CanvasGl::create();
    }

    void draw() override {
        mCanvas->begin( getWindowSize() );

        vg::Paint paint;
        paint.setColor( ColorAf( 0.2f, 0.7f, 1.0f ) );
        mCanvas->fillCircle( vec2( 200, 200 ), 80, paint );

        mCanvas->end();
    }
};

In window mode, the canvas automatically detects MSAA settings and configures itself appropriately. On most platforms, it uses an internal framebuffer with PLS or atomic mode for analytical anti-aliasing, then blits the result to your window.

Offscreen Rendering

To render to a texture for post-processing or capture:


// Create an offscreen canvas with explicit dimensions
mCanvas = vg::CanvasGl::create( 1920, 1080 );

void draw() override {
    // Render to internal FBO
    mCanvas->begin( mCanvas->getFboSize() );
    // ... drawing commands ...
    mCanvas->end();

    // Use the resulting texture
    gl::draw( mCanvas->getTexture(), getWindowBounds() );
}

Offscreen mode always uses atomic mode for consistent analytical anti-aliasing, regardless of window MSAA settings. The internal texture format is RGBA16F.

Direct3D 12 (Experimental)

A Direct3D 12 backend is available via CanvasD3d12 for Windows applications. This backend is currently experimental and may have limitations. The API mirrors CanvasGl, so switching backends requires minimal code changes.

Canvas Configuration

The canvas supports several rendering modes that affect quality and performance. Understanding these is important for getting the best results on your target platform.

PLS, Atomic, and MSAA Modes

The Rive renderer supports multiple anti-aliasing strategies, each with different capabilities:

Mode Description AA Quality Feathering Requirements
PLS Pixel Local Storage for coverage-based AA Best Full support GL 4.5+ with GL_EXT_shader_framebuffer_fetch
Atomic Atomic operations for analytical AA Excellent Full support GL 4.5+ with shader atomics
MSAA Traditional multisample anti-aliasing Good Limited Any GL version (fallback)

Feature Comparison by Mode

Feature PLS Atomic MSAA
Feathering (soft edges) Yes Yes Reduced quality
Analytical AA Yes Yes No (sample-based)
Complex blend modes Full Full Full
Performance Best Good Varies with sample count
Memory usage Low Moderate High (scales with MSAA level)

The canvas auto-selects the best available mode. On desktop Windows/Linux with GL 4.5+, PLS or atomic mode is preferred. The canvas creates an internal FBO to ensure consistent rendering regardless of your window's MSAA settings.

Clockwise Fill Override

The clockwiseFillOverride setting enables feathering support. This is enabled by default in CanvasGl. When enabled:

  • Feathering (soft edges) works on fills and strokes
  • Requires disableRasterOrdering = true (atomic mode)
  • May slightly affect fill rule interpretation for complex self-intersecting paths

Platform Differences

Platform GL Version Default Mode Feathering
Windows 4.5+ PLS or Atomic Full support
Linux 4.5+ PLS or Atomic Full support
macOS 4.1 MSAA only Reduced quality
macOS Note: Due to OpenGL 4.1 limitations, macOS always uses MSAA mode. PLS and Fragment Shader Interlock are not available. Feathering will still work but with reduced quality compared to PLS/Atomic modes.

Transform Stack

The canvas maintains a transform stack similar to HTML5 Canvas. Use save() and restore() to push and pop the current transform and clip state:


mCanvas->save();

mCanvas->translate( vec2( 100, 100 ) );
mCanvas->rotate( glm::radians( 45.0f ) );
mCanvas->scale( vec2( 2.0f, 1.0f ) );

mCanvas->fillRect( Rectf( -50, -25, 50, 25 ), paint );

mCanvas->restore();  // Transform reverted

The mat3 Transform Matrix

Internally, transforms are represented as a 3x3 matrix. Each transform operation modifies this matrix:

sx shx tx
shy sy ty
0 0 1

sx, sy = scale    shx, shy = shear    tx, ty = translation

Available transform methods:

  • translate( const vec2& offset )
  • rotate( float radians )
  • scale( const vec2& s )
  • transform( const mat3& m ) – concatenate matrix
  • setTransform( const mat3& m ) – replace matrix
  • resetTransform()
  • getTransform() – returns current mat3

Paint and Styling

The Paint class controls visual appearance of drawn shapes. It supports solid colors, gradients, stroke styling, feathering, and blend modes.

Solid Colors


vg::Paint paint;
paint.setColor( ColorAf( 1.0f, 0.5f, 0.2f ) );      // RGBA
paint.setColor( Color( 0.2f, 0.7f, 1.0f ) );        // RGB (alpha = 1)
paint.setOpacity( 0.8f );                            // Multiply alpha

Gradients

Linear Gradient:


paint.setLinearGradient(
    vec2( 0, 0 ),      // start point
    vec2( 200, 0 ),    // end point
    ColorAf( 1, 0, 0 ),  // start color
    ColorAf( 0, 0, 1 )   // end color
);

Radial Gradient:


paint.setRadialGradient(
    vec2( 100, 100 ),  // center
    80.0f,             // radius
    ColorAf( 1, 1, 0 ),  // inner color
    ColorAf( 1, 0, 0 )   // outer color
);

Multi-stop Gradients:


std::vector<vg::GradientStop> stops = {
    { 0.0f, ColorAf( 1, 0, 0 ) },
    { 0.5f, ColorAf( 0, 1, 0 ) },
    { 1.0f, ColorAf( 0, 0, 1 ) }
};
paint.setLinearGradient( vec2( 0, 0 ), vec2( 200, 0 ), stops );

Gradient Spread Modes:


paint.setGradientSpread( vg::GradientSpread::Pad );     // Extend edge colors (default)
paint.setGradientSpread( vg::GradientSpread::Repeat );  // Tile the gradient
paint.setGradientSpread( vg::GradientSpread::Reflect ); // Mirror at edges

Stroke Properties

Stroke Width:


paint.setStrokeWidth( 5.0f );

Line Cap: Controls how line endpoints are drawn.


paint.setLineCap( vg::LineCap::Butt );    // Flat end at exact endpoint
paint.setLineCap( vg::LineCap::Round );   // Semicircle at endpoint
paint.setLineCap( vg::LineCap::Square );  // Extends by half stroke width

Line Join: Controls how line segments connect at corners.


paint.setLineJoin( vg::LineJoin::Miter );  // Sharp corner (default)
paint.setLineJoin( vg::LineJoin::Round );  // Rounded corner
paint.setLineJoin( vg::LineJoin::Bevel );  // Flat corner

Miter Limit: When using miter joins, limits the spike length for sharp angles.


paint.setMiterLimit( 4.0f );  // Default is 4

Dashing: Create dashed or dotted lines.


// Pattern: 10px on, 5px off, 3px on, 5px off
paint.setDash( { 10.0f, 5.0f, 3.0f, 5.0f }, 0.0f );

Feathering (Soft Edges)

Feathering creates soft, blurred edges on shapes—a unique feature of the Rive renderer:


paint.setFeather( 15.0f );  // 15 pixel blur radius
mCanvas->fillCircle( center, radius, paint );
Note: Feathering requires PLS or Atomic mode for full quality. On macOS (MSAA mode), feathering still works but with reduced quality. See the mode comparison table for details.

Blend Modes

Standard Porter-Duff and Photoshop-style blend modes are supported:


paint.setBlendMode( vg::BlendMode::SrcOver );     // Default (normal alpha blending)
paint.setBlendMode( vg::BlendMode::Multiply );
paint.setBlendMode( vg::BlendMode::Screen );
paint.setBlendMode( vg::BlendMode::Overlay );
// ... Darken, Lighten, ColorDodge, ColorBurn, HardLight, SoftLight,
//     Difference, Exclusion, Hue, Saturation, Color, Luminosity

Drawing Functions

Primitives

Common shapes have dedicated methods for convenience:


// Filled shapes
mCanvas->fillRect( Rectf( 10, 10, 100, 80 ), paint );
mCanvas->fillRoundedRect( Rectf( 10, 10, 100, 80 ), 10.0f, paint );
mCanvas->fillCircle( vec2( 50, 50 ), 30.0f, paint );
mCanvas->fillEllipse( vec2( 50, 50 ), vec2( 40, 20 ), paint );

// Stroked shapes
mCanvas->strokeRect( rect, paint );
mCanvas->strokeRoundedRect( rect, radius, paint );
mCanvas->strokeCircle( center, radius, paint );
mCanvas->strokeEllipse( center, radii, paint );
mCanvas->drawLine( p0, p1, paint );

Paths

For complex shapes, use Cinder's Path2d or Shape2d:


Path2d path;
path.moveTo( 100, 100 );
path.lineTo( 200, 100 );
path.quadTo( 250, 150, 200, 200 );
path.curveTo( 150, 250, 100, 200, 100, 150 );
path.close();

mCanvas->fillPath( path, paint, vg::FillRule::NonZero );
mCanvas->strokePath( path, strokePaint );

Fill Rules:

Rule Description
FillRule::NonZero Non-zero winding rule (default). A point is inside if a ray from it crosses more clockwise edges than counter-clockwise.
FillRule::EvenOdd Even-odd rule. A point is inside if a ray from it crosses an odd number of edges.

Images

Draw textures using the Image class:


// Create from Cinder texture
gl::Texture2dRef texture = gl::Texture2d::create( loadImage( loadAsset( "photo.jpg" ) ) );
vg::ImageRef image = mCanvas->createImage( texture );

// Draw at position
mCanvas->drawImage( image, vec2( 100, 100 ) );

// Draw stretched to rectangle
mCanvas->drawImage( image, Rectf( 0, 0, 400, 300 ) );

// Draw sub-region
mCanvas->drawImage( image,
    Rectf( 0, 0, 100, 100 ),    // source rect
    Rectf( 50, 50, 250, 250 )   // dest rect
);

// Arbitrary mesh mapping
mCanvas->drawImageMesh( image, vertices, uvs, indices, opacity );

Text


Font font = Font( "Arial", 24 );
mCanvas->drawString( "Hello, Vector Graphics!", vec2( 50, 100 ), font, paint );

// Or create a path from text for effects
vg::CachedPathRef textPath = mCanvas->createTextPath( "Outlined", font );
mCanvas->strokePath( textPath, strokePaint );

Clipping

Clips restrict drawing to a region. They accumulate (intersect) within save/restore blocks:


mCanvas->save();

// Rectangular clip
mCanvas->clipRect( Rectf( 50, 50, 200, 200 ) );

// Path clip (can use any shape)
Path2d clipPath;
clipPath.arc( vec2( 150, 150 ), 80, 0, M_PI * 2 );
mCanvas->clipPath( clipPath );

// All subsequent drawing is clipped to the intersection
mCanvas->fillRect( Rectf( 0, 0, 400, 400 ), paint );

mCanvas->restore();  // Clip state restored

Performance Optimization

The cinder::vg API provides several mechanisms for optimizing repeated drawing operations.

CachedPath

When drawing the same path multiple times, create a CachedPath to avoid repeated CPU-side path conversion:


// Create once
vg::CachedPathRef cachedPath = mCanvas->createPath( complexShape );

// Draw many times (GPU representation is reused)
for ( const vec2& position : positions ) {
    mCanvas->save();
    mCanvas->translate( position );
    mCanvas->fillPath( cachedPath, paint );
    mCanvas->restore();
}

When to use: Any path drawn more than once per frame, especially complex paths with many segments.

FrozenPath

For maximum performance, FrozenPath pre-tessellates the path, skipping expensive Wang's formula calculations during drawing:


// Create cached path first
vg::CachedPathRef cachedPath = mCanvas->createPath( shape );

// Freeze at current transform scale (expensive operation)
vg::FrozenPathRef frozenFill = mCanvas->freezePathFill( cachedPath, paint );
vg::FrozenPathRef frozenStroke = mCanvas->freezePathStroke( cachedPath, strokePaint );

// Draw very efficiently
mCanvas->drawFrozenPath( frozenFill, paint );
Important: FrozenPath tessellation is computed at a specific scale. The path will render correctly under translation and rotation, but may show artifacts if drawn at a significantly different scale. Create new frozen paths when scale changes substantially.

When to use: Particle systems, repeated icons, UI elements that don't change scale.

DisplayList

Record complex drawing sequences for efficient replay:


// Record once
vg::DisplayListRef displayList = mCanvas->createDisplayList();
displayList->beginRecording( mCanvas.get() );

mCanvas->draw( complexSvgDoc );  // Commands captured

displayList->endRecording();

// Replay efficiently each frame
void draw() {
    mCanvas->begin( size );
    displayList->replay( mCanvas.get() );
    mCanvas->end();
}

When to use: Static SVG content, complex scenes that don't change, UI backgrounds.

Instanced Drawing

Draw many identical shapes efficiently with a single call:


std::vector<vec2> positions;
// ... fill with particle positions ...

// Single draw call for all circles
mCanvas->drawCircles( positions, 5.0f, paint );

// Or with full transforms
std::vector<mat3> transforms;
mCanvas->drawCircles( transforms, 5.0f, paint );

// Works with cached and frozen paths too
mCanvas->drawPaths( positions, cachedPath, paint );
mCanvas->drawFrozenPaths( positions, frozenPath, paint );

Limitations

General

  • Thread safety: Canvas instances are not thread-safe. Serialize access or use one canvas per thread.
  • Nested frames: Cannot call begin() while already in a frame. Check with inFrame().

OpenGL (CanvasGl)

  • MSAA interaction: Cannot render directly to MSAA framebuffers. The canvas creates an internal non-MSAA FBO and blits to your target.
  • GL state: Extensive GL state modification occurs during rendering. State is saved and restored, but custom GL code should not assume state persistence across canvas calls.
  • macOS: Limited to GL 4.1. No PLS or FSI support—always uses MSAA mode. Feathering quality reduced.

Path Rendering

  • FrozenPath scale: Tessellation is scale-dependent. Significant scale changes may cause visual artifacts.
  • Precision: Rive uses float32 internally. Extremely large coordinates may lose precision.

Feathering

  • Requires atomic mode (disableRasterOrdering = true)
  • Requires clockwiseFillOverride = true
  • Both settings are configured automatically in CanvasGl
  • On MSAA-only platforms (macOS), feathering works but with reduced quality
